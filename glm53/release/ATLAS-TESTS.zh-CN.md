# Expert Atlas：按哪些选择重新排序专家

控制面板的**专家优化**在一个分配所含的位宽之间重新排序路由专家：模型选中最多的专家获得最宽的位宽，内存用量不变。排序可以依据读取提示词时（prefill）选中的专家、生成 token 时（decode）选中的专家，或两者的混合。本页给出每种依据的改善率（重新排序消除了多少 3 bit 造成的损失），在 DGX Spark 上，针对 8,192 个 token 的文档以及 128K 和 256K token 的提示词测得。

## 摘要

- **prefill 和 decode 使用不同的专家。** 在 174 个提示词上，某一层在 prefill 中被选中最多的 64 个专家与在 decode 中被选中最多的 64 个专家有 42 % 相同，而随机选择时为 25 %。层越深，两个列表的差异越大。同一个提示词的 prefill 选择与 decode 选择之间的相似程度，低于不同类工作的两个提示词的 prefill 选择之间的相似程度。
- **加大 decode 选择的权重有利于 decode 位置（模型的回复），直到权重约为 0.7。** 在 8,192 个 token 时，按 decode 选择排序的改善率为 25 %，按 prefill 选择排序为 13 %。在 128K 和 256K token 时，decode 权重 0.7 得到 34 % 和 32 %，只用 prefill 选择得到 28 % 和 21 %；从 0.5 起，增益趋于平稳。
- **prefill 位置（提示词）几乎不取决于权重。** 各权重的改善率：8,192 个 token 时为 15 至 21 %，128K token 时除一个低值外为 15 至 25 %，256K token 时为 21 至 24 %；权重之间的差异都在测量的波动范围内。
- **因此，面板的 Both 以 0.7 加权专家的 decode 占比、以 0.3 加权其 prefill 占比。** decode 和 prefill 各自只按一种来源排序。

## 重新排序前后的 KL：四台 DGX Spark，一半 3 bit、一半 4 bit，权重 0.7

相对于所有路由专家均为 4 bit 的模型的 KL 散度（该模型自身的值为 0），取参与评分的位置上的均值，分别为重新排序之前（“未优化”）和用面板的 Both（*w* = 0.7）重新排序之后的值。改善率 = 1 − KL(*w* = 0.7) / KL(未优化)：即 3 bit 造成的损失中被重新排序消除的比例。

| 提示词 | 位置 | 未优化 | *w* = 0.7 | 改善率 |
|---|---|---|---|---|
| 8,192 token | decode | 0.02443 | 0.01848 | 24.4 % |
| 8,192 token | prefill ¹ | 0.02352 | 0.01990 | 15.4 % |
| 128K token | decode ² | 0.01364 | 0.00899 | 34.1 % |
| 128K token | prefill ² | 0.01149 | 0.00964 | 16.1 % |
| 256K token | decode ² | 0.01401 | 0.00949 | 32.3 % |
| 256K token | prefill ² | 0.00412 | 0.00321 | 22.1 % |

¹ 不含未优化时 KL 最大的 1 % 位置；简单均值为 0.04273 和 0.04384（−2.6 %），由几十个位置决定。
² 不含在任一分配的 KL 中属于最大 1 % 的每个位置（101 至 135 个位置）。简单均值如下：

| 提示词 | 位置 | 未优化 | *w* = 0.7 | 改善率 |
|---|---|---|---|---|
| 128K token | decode | 0.02221 | 0.01389 | 37.5 % |
| 128K token | prefill | 0.06075 | 0.04605 | 24.2 % |
| 256K token | decode | 0.02171 | 0.01423 | 34.5 % |
| 256K token | prefill | 0.01635 | 0.01284 | 21.5 % |

下文结果中的比例是按每 32 个位置一块计算的（为了得出其 95 % 区间），与这里的值最多相差两个百分点。

## 测量方法

- **硬件和权重。** DGX Spark，本发布版本。路由专家来自 3 bit 和 4 bit bank，两种位宽各占一半（9,600 + 9,600 个专家，平均 3.5 bit）；其他权重来自八节点检查点。
- **分配。** 每个权重 *w* 生成一个分配。专家的得分为 *w* × 它在所在层 decode 选择中的占比 + (1 − *w*) × 它在所在层 prefill 选择中的占比。所有层一起排名（与启动器的排序方式相同），得分最高的专家获得 4 bit。因此 *w* = 0 按 prefill 选择排序，*w* = 1 按 decode 选择排序，*w* = 0.7 就是面板的 Both。“未优化”是起始分配：每层内位宽交替排列。
- **排序的学习数据。** 12 类工作的 162 个提示词的选择：智能体对话、编程、日文和英文文本、Linux 运维和服务器安全，使用日语和英语，每个生成 500 个 token。下文的测试文本都不在其中。
- **度量。** 下一个 token 的分布相对于所有路由专家均为 4 bit 的同一模型的 KL 散度，逐位置计算，文本以 teacher forcing 方式给定。评分配置是确定性的：提示词分块为 2,048 行，不使用提示词专家内核，使用 FP8 KV 缓存，因此同一分配每次运行都得到相同的 logits。改善率为 1 − KL(分配) / KL(未优化)：即 3 bit 专家造成的损失中被重新排序消除的比例。95 % 区间通过对每 32 个位置一块的分块进行重采样得到。
- **prefill 位置和 decode 位置。** prefill 位置预测提供给模型的文档的 token（prefill 读取的文本）。decode 位置预测模型自己对该文档的回复的 token（其思考文本，以温度 0.6 采样；decode 写出的文本），这些 token 接在文档之后以 teacher forcing 方式给定。两者的评分方式相同；名称表示位置位于哪段文本中。整个文档也按该分配计算，因此 decode 位置也包含了以较少的 bit 读取文档的代价。
- **窗口开头没有聊天模板。** 在模板的用户轮次内，无论长度如何，模型对用户自己的文本预测都很差（在一次检查中，其最可能的 token 与文本一致的位置约占四分之一；去掉模板开头后为 96 至 98 %）。因此窗口从文档内部开始，prefill 位置衡量的是模型对文档本身的跟随程度。

## 结果：8,192 个 token 的文档，12 类工作

四台 DGX Spark（TP=4），基准也如此。十二个未参与学习的提示词，每类工作一个，每个给出两个 8,192 个 token 的窗口。文档窗口是提示词的最后 8,192 个 token；回复窗口是提示词的最后 7,168 个 token，后接模型回复的前 1,024 个 token。对每个窗口的最后 1,023 个位置评分，每种位置共 12,276 个。

| 分配 | decode：改善率 [95 %] | prefill：改善率 [95 %] |
|---|---|---|
| *w* = 0（prefill） | 13 % [7, 18] | 17 % [1, 25] |
| *w* = 0.2 | 19 % [14, 22] | 21 % [3, 28] |
| *w* = 0.3 | 21 % [16, 25] | 17 % [−2, 27] |
| *w* = 0.4 | 20 % [16, 22] | 19 % [−4, 28] |
| *w* = 0.5 | 19 % [14, 23] | 19 % [5, 26] |
| *w* = 0.7（Both） | 24 % [20, 28] | 15 % [−4, 23] |
| *w* = 1（decode） | 25 % [22, 29] | 16 % [3, 26] |

未优化时的 KL：prefill 位置 0.0427（中位数 0.0016），decode 位置 0.0244（中位数 0.0044）。prefill 列不含最差的 1 % 位置。这些位置占 prefill 位置 KL 的约一半，且在不同分配之间变化太大，无法用简单均值比较。

## 结果：128K 和 256K token 的提示词，编程和 Linux 运维

基准（所有路由专家均为 4 bit）在八台 DGX Spark 上运行（TP=8），各分配在四台上运行（TP=4）。每种大小四个未参与学习的提示词：两个编程（某种语言标准库的源文件和头文件），两个 Linux 运维（手册页、系统日志和配置文件），每个都以一项任务结尾。模型对每个提示词的回复以温度 0.6 采样。窗口是去掉聊天模板开头 token 的提示词，后接回复的前 1,024 个 token：131,062 个 token（128K）和 262,134 个 token（256K）。对每个窗口的最后 2,047 个位置评分，约 1,023 个 prefill 和 1,024 个 decode，因此每种大小、每种位置有 4,092 至 4,098 个位置。

两种位置对所有分配都同样地排除任一分配（包括起始分配）的 KL 中属于最差 1 % 的每个位置：每种位置、每种大小 101 至 135 个。prefill 位置的简单均值由几十个位置决定，在不同分配之间的波动达百分之几十。

**decode 位置：改善率 [95 %]**

| 分配 | 128K | 256K |
|---|---|---|
| *w* = 0（prefill） | 28 % [21, 33] | 21 % [17, 26] |
| *w* = 0.3 | 31 % [24, 37] | 29 % [25, 33] |
| *w* = 0.5 | 33 % [27, 38] | 30 % [25, 35] |
| *w* = 0.7（Both） | 34 % [29, 40] | 32 % [28, 36] |
| *w* = 1（decode） | 33 % [27, 39] | 33 % [29, 36] |

**prefill 位置：改善率 [95 %]**

| 分配 | 128K | 256K |
|---|---|---|
| *w* = 0（prefill） | 24 % [12, 35] | 24 % [11, 35] |
| *w* = 0.3 | −2 % [−19, 12] | 21 % [6, 33] |
| *w* = 0.5 | 25 % [14, 34] | 23 % [11, 33] |
| *w* = 0.7（Both） | 15 % [1, 27] | 24 % [13, 33] |
| *w* = 1（decode） | 15 % [0, 28] | 24 % [10, 35] |

**最可能的 token 与基准不同的位置**（decode / prefill）

| 分配 | 128K | 256K |
|---|---|---|
| 未优化 | 3.8 % / 2.3 % | 4.0 % / 1.2 % |
| *w* = 0（prefill） | 3.1 % / 1.9 % | 3.4 % / 1.0 % |
| *w* = 0.3 | 3.3 % / 2.3 % | 3.4 % / 1.2 % |
| *w* = 0.5 | 3.1 % / 2.2 % | 3.2 % / 0.9 % |
| *w* = 0.7（Both） | 3.0 % / 1.9 % | 3.2 % / 1.0 % |
| *w* = 1（decode） | 3.0 % / 2.2 % | 3.3 % / 1.2 % |

在 decode 位置上，两类工作有所不同：编程的改善率随 decode 权重一路上升（128K：*w* = 0 时 13 %，0.5 时 18 %，1 时 27 %；256K：17 %、28 %、30 %），Linux 运维从 0.3 起趋于平稳（128K：35 %、40 %、37 %；256K：25 %、32 %、33 %）。prefill 的那个低值（128K 的 *w* = 0.3）在 256K 和 8,192 个 token 时没有出现。

## 说明

- 基准是所有路由专家均为 4 bit 的模型，而不是 BF16 模型。测得的损失是 3 bit 专家相对于 4 bit 专家的损失。
- 在 128K 和 256K 时，基准在八个节点上运行，各分配在四个节点上运行。节点数给 KL 增加的量都包含在每个分配的值和起始分配的值中，没有单独测量。
- 长提示词每种大小四个，属于两类工作。回复是思考文本；最终回答和工具调用没有单独测量。
- 重新排序从给它的选择中学习。直接用这些选择离线测量时，对于学习数据中没有的工作类型，它捕获的可能增益较少：约为对学习数据中已有工作所捕获增益的三分之二。
