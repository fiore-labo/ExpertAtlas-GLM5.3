# glm53.conf の設定項目

`glm53.conf` には、レーンの設定（ノード、ネットワーク、重み、drafter、サーバー、メモリ、コントロールパネル）を書きます。シェルのファイルで、1 台目のノードの `tf-glm53` と同じディレクトリに置き、手で書いて編集します。`glm53.t4.conf.example`（4 台）か `glm53.conf.example`（8 台）を `glm53.conf` にコピーし、ノード、ネットワークのデバイス、パスを書き入れてください。それ以外の項目は、例に実測した値が入っています。

## 誰が読むか、変更がいつ効くか

- `tf-glm53` は、コマンドを実行するたびに読みます。読むのは 1 台目のノードのファイルだけです。`tf-glm53 deploy` はこのディレクトリを `glm53.conf` を除いて他のノードにコピーし、各ランクは起動するときに 1 台目から設定を受け取ります。
- 動いているエンジンは、起動したときの設定のままです。変更がエンジンに届くのは次の起動からです（`./tf-glm53 down` のあと `./tf-glm53 up`。またはコントロールパネルで「停止」のあと「起動」）。
- コントロールパネルのランチャーは、ランチャーを起動したときに読みます。編集したら、ランチャーを起動し直してください: `./tf-glm53 launcher stop` のあと `./tf-glm53 launcher`。その間エンジンは動いたままでかまいません。ランチャーは動いているエンジンを見つけます。
- ほかに書き換えるものはありません。例外は 1 つだけで、起動画面のノードの一覧で「保存」すると `NODES` を書きます（前のファイルは `glm53.conf.bak-<時刻>` として横に残ります）。ランチャーはその `NODES` をすぐに読み直します。
- 起動画面で起動ごとに選ぶもの（expert の幅、KV の形式、文脈、ストア、drafter、各ノードが OS に残す量）は、その起動の間だけのもので、`glm53.conf` には書きません。ランチャーはこれらを環境変数（`LAUNCH_*`）で `tf-glm53` に渡します。このファイルの設定項目ではありません。
- ページ自身の設定（色、円の並べ方など）は `launch/panel-settings.json` に残ります。
- `glm53.conf` はリリースのファイルではありません。`SHA256SUMS` に載っていないので、`tf-glm53 check` も `tf-glm53 deploy` も照合しません。大きく変える前に、動いているファイルの控えを取ってください。
- 別の設定ファイル: `tf-glm53 -c FILE コマンド`（ランチャーも `./tf-glm53 -c FILE launcher`）。同じノードで 2 つのレーンを動かすなら、`PORT`、`MASTER_PORT`、`LAUNCHER_PORT` をそれぞれ別にします。

## 設定項目

「既定」は、項目が無いか空のときに `tf-glm53` が使う値です。「（必須）」には既定がありません。**パネル** と書いた項目は、起動画面で起動ごとに選び直せます。ファイルの値は `tf-glm53 up` が使います。

### ノードとネットワーク

| 項目 | 既定 | 意味 |
|---|---|---|
| `NODES` | （必須） | ノードをランク順に、RDMA ネットワークのアドレスで、シェルの配列として書きます: `NODES=(192.0.2.11 192.0.2.12 192.0.2.13 192.0.2.14)`。4 台か 8 台です。`tf-glm53` は 1 台目で実行します。各ノードは他のノードにパスワードなしの ssh で入れること。起動画面で worker（1 台目以外）を変えて、ここに保存できます。 |
| `SOCKET_IFNAME` | （必須） | 各ノードでのそのネットワークのインターフェース（`ip -br addr`）。例: `enp1s0f1np1`。 |
| `IB_HCA` | （必須） | そのインターフェースの RDMA デバイス（`ibv_devices`）。例: `rocep1s0f1`。 |
| `GID_INDEX` | 空 | RoCE v2 の GID の番号。空なら各ノードで探します（IPv4 アドレスを持つ最後の RoCE v2 の項目）。 |
| `MASTER_PORT` | `29551` | NCCL のランデブーに使う 1 台目のポート。 |

### ランクの動かし方

| 項目 | 既定 | 意味 |
|---|---|---|
| `RUNTIME` | `host` | `host`: このディレクトリから動かします。各ノードに cuBLAS 13、libibverbs、NCCL が要ります。`docker`: 各ランクを `IMAGE` のコンテナで動かします（RUNTIME.ja.md「コンテナで動かす」）。 |
| `IMAGE` | 空 | `RUNTIME=docker` のとき、このリリースのイメージ。 |
| `NCCL_LIB` | `~/nccl-2.30.7/nvidia/nccl/lib/libnccl.so.2` | 各ノードのこのパスにある NCCL 2.30.7（`RUNTIME=host` のときだけ。RUNTIME.ja.md「初回起動の前に」）。 |

### 重みと drafter

| 項目 | 既定 | 意味 |
|---|---|---|
| `WEIGHTS` | （必須） | チェックポイントのディレクトリ。全ノードで同じパスにします。4 台は `GLM-5.3-EXL3-4x-DGX-Sparks`、8 台は `GLM-5.3-EXL3-8x-DGX-Sparks`。 |
| `DRAFTER_KIND` | `mtp` | **パネル**。モデルが確かめるトークンを何が下書きするか: `mtp`（チェックポイントの MTP 層）、`dflash2`（`DRAFTER` のモデル）、`none`。`./tf-glm53 -d KIND up` でその起動だけ別のものにできます。 |
| `MTP_K` | `3` | MTP の 1 ラウンドの下書きの数。1〜7。 |
| `DRAFTER` | 空 | DFlash2 のモデルのディレクトリ。全ノードで同じパスにします。`DRAFTER_KIND=dflash2` にはこれが要ります。起動画面が DFlash2 を選ばせるのも、これが設定され、全ノードにモデルがあるときだけです。リリースには含まれません（RUNTIME.ja.md「DFlash2 を使う手順」）。 |
| `DRAFT_SAVES` | `8` | `CACHE=pool` と DFlash2 のとき、リクエストの間で drafter の状態を残す会話の数。 |

### サーバー

| 項目 | 既定 | 意味 |
|---|---|---|
| `NAME` | `glm-5.3` | API でのモデルの名前。`/v1/models` に載り、応答に付きます（リクエストはどの名前を指定してもかまいません）。 |
| `HOST` | `0.0.0.0` | API が待ち受けるアドレス。`0.0.0.0` は全アドレスです。API にキーはないので、届く人なら誰でも使えます。閉じたネットワーク内に留めるか、前段に TLS とアクセス制御を置いてください。`127.0.0.1` にすると 1 台目のノードからだけになり、他のマシンからは ssh トンネルで使います。 |
| `PORT` | `8000` | API のポート。 |
| `METRICS_LISTEN` | 空 | `HOST:PORT`。1 台目のノードがそのアドレスでも `GET /metrics`（Prometheus のテキスト）と `GET /health` に読み取り専用で答えます。別のホストのモニタ用です。空なら使いません。 |
| `EXPERT_LIVE` | `1` | `1`: 1 台目のノードが、プロンプトの各行と decode の各トークンが選ぶ expert を、コントロールパネルのために数えます（実測の表示、利用記録、エキスパート最適化）。`0`: 数えません。パネルは動いているエンジンと「停止」を出しますが、選択の表示と最適化はありません。パネルからの起動はいつも数えます。 |

### 文脈、キャッシュ、KV

| 項目 | 既定 | 意味 |
|---|---|---|
| `CONTEXT` | `819200` | **パネル**。1 つのリクエストが届く位置の数（プロンプト + 応答）。 |
| `STORE` | `819200` | **パネル**。`CONTEXT` のほかに、前の会話のために残す位置の数。`CACHE=pool` では 512 以上。 |
| `CACHE` | `pool` | `pool`: `CONTEXT` + `STORE` の位置を、全会話が共有する 256 位置のブロックで持ちます。`slots`: 会話ごとに `STORE` 位置のストアを 1 つ持ちます。 |
| `KV` | `fp8` | **パネル**。KV キャッシュの形式: `fp8`、または `fp4`（1 位置あたりのメモリが少なく、精度が少し下がります。T4.ja.md）。 |
| `DCP` | `2` | decode の文脈並列: `2` は KV をペアのランクで分け、`1` は各ランクに全部を持ちます。`CACHE=pool` は 1 か 2。 |
| `ROWS` | `8192` | プロンプトのチャンクの行数（4 台の例では `16384`）。 |
| `SP_PARTS` | `4` | プロンプトのチャンクを分ける系列並列の数。 |

### メモリと起動

| 項目 | 既定 | 意味 |
|---|---|---|
| `NEED_GB` | `112` | 起動の前に各ノードで使えなければならない GiB（`tf-glm53 check`）。DFlash2 では 3 多く、`STORE` が 819,200 より 100,000 位置少ないごとに 2.7 少なくなります。4 台の例は 131 で、その `STORE` で 112 になります。パネルからの起動は、計画の値を代わりに使います。 |
| `READY_TIMEOUT` | `900` | `tf-glm53 up` がサーバーを待つ秒数。 |

### コントロールパネル

| 項目 | 既定 | 意味 |
|---|---|---|
| `LAUNCHER_HOST` | `0.0.0.0` | パネルが待ち受けるアドレス。キーはないので、届く人なら誰でもエンジンの起動・停止・変更ができます。`127.0.0.1` にすると 1 台目のノードからだけになり、他のマシンからは ssh トンネルで開きます（`ssh -L 8010:127.0.0.1:8010 FIRST-NODE`）。 |
| `LAUNCHER_PORT` | `PORT` + 10 | パネルのポート（4 台の例では 8010）。`http://FIRST-NODE:LAUNCHER_PORT/panel` で開きます。 |
| `RESERVE_GB` | `4` | **パネル**。パネルから起動したあと、各ノードが OS に残す GiB。2〜32。 |
| `ATLAS_DIR` | このディレクトリの `atlas/` | 保存した割り当ての置き場所（`allocs/user/<名前>.json`）。 |
| `ATLAS_GENERIC` | `1` | `1`: パネルからの起動で全層を汎用の grouped カーネルで動かし、エキスパート最適化がどの expert でも動かせるようにします。 |
| `LAUNCH_SNAPSHOTS` | `0` | `1`: 起動と停止の前後に、各ノードの GPU、メモリ、ログの末尾を `snapshots/` に書きます。 |
| `LAUNCH_DROP_CACHES` | `0` | `1`: 起動の前に全ノードでページキャッシュを捨てます（パスワードなしの `sudo` が要ります）。 |

### ランクに渡す環境変数

| 項目 | 既定 | 意味 |
|---|---|---|
| `EXTRA_ENV` | 空 | 全ランクに渡す環境変数（`名前=値` を空白で区切り、引用符で囲みます）。例: `EXTRA_ENV="TF_GLM53_MULTI=4"`（最大 4 つの会話をまとめて decode。`glm53.conf.example`）。ランチャーも、いくつかを自分で読みます。`TF_PANEL_HTML`（別のページを出す）と `TF_PANEL_SETTINGS`（ページの設定の別のファイル）などです。 |
