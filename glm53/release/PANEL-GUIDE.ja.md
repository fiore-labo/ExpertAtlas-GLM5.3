# Expert Atlas: コントロールパネル

パネルはランチャーが `http://<先頭ノード>:<ランチャーのポート>/panel` に出します。既定では全アドレスで、キーなしで待ち受けるので、
パネルに届く人は誰でもエンジンの起動・停止・変更ができます。閉じたネットワーク内に留めてください (`LAUNCHER_HOST=127.0.0.1` に
すると先頭ノードからだけになり、ほかの機械からは ssh のトンネル `ssh -L 8010:127.0.0.1:8010 <先頭ノード>` のあと
`http://127.0.0.1:8010/panel` で開きます)。
画面は 2 つあり、自動で切り替わります: エンジンが止まっている間は起動画面、動いている間は稼働パネルです。このリリースの
パネルは 4 ノードか 8 ノードで動きます (台数は起動画面の ノード で選びます)。

サークルは routed expert 19,200 個の地図です。内側が層 3、外側が層 77 で、1 周が 256 個です。

## 起動画面 (エンジン停止中)

- **計画** ([ BIT ALLOC ]): 各 expert を何 bit で読むかを決めます。画面は新しい計画で開きます (割合は前回の稼働のもの。稼働が
  まだ無いときは全部 3 bit)。前回の稼働の割り当てそのものや保存した割り当ては 開く で選びます。カードの見出しに、
  今の計画が何かを出します: 新規 · 未保存、前回の稼働、保存した割り当ての名前。
  - **割合**: 表に bit 幅ごとの expert の割合を入れます (5・4・3 bit。残りはデータのある一番狭い幅になり、合計はいつも
    100%)。曲線上のつまみを動かしても決められます。目盛りは 5 bit の端を 100% として数えます: 5 bit 10% は範囲
    100〜90% です。混ぜるときは、よく使われる expert ほど広い bit になります。並べる回数は prefill 0.3 / decode 0.7
    (expert の decode の割合を 0.7、prefill の割合を 0.3 で重みづけ。`ATLAS-TESTS.ja.md`) です。
  - **利用記録** (decode / prefill / prefill 0.3 / decode 0.7): 見るためのボタンです。選んだ回数で、曲線とつまみの読み
    (使用順で上から並べた expert が選択の何 % を持つか)、サークルの並び、利用率を出します。計画の bit は変わりません。
    計画の bit が表示と別の回数で並んでいるとき (開いた割り当て、利用記録 が prefill 0.3 / decode 0.7 以外) は、領域を
    薄くして「領域は目安」と出します。本当の bit は曲線の下の帯です。
  - **新しい計画**: 割合を変える (入力かつまみ) と新しい計画 (新規 · 未保存) になり、計画の利用記録 (下) の順に並べます。
  - **開く**: 前回の稼働の割り当てと、保存した割り当ての一覧です。割合、平均 bit、いつ・どう作ったかが出ます。開いたものは
    bit そのまま計画になり、起動はその割り当てを使います。利用記録も一緒に付いてきます: 利用記録 と曲線はそれを出し、そこから
    割合を変えた計画もそれで並べ、どちらから起動した稼働もそれに足されます。割合を変えるまで bit は保存したままです。
    データの無い幅や、このレーンに無い bank を使う割り当ては開けません (理由を下に出します)。保存したものは 名前の変更 と
    削除 (もう一度押して確定) ができます。削除したものはランチャーのごみ箱へ移ります。
  - **保存**: 自動では保存しません。計画は、その稼働を止めるときに利用記録と一緒に保存します (下の 保存して停止。稼働パネルの
    保存 でもいつでも)。
- **利用記録**: 保存した割り当ては、それを保存した稼働の利用記録 (expert ごとの選ばれた回数、decode と prefill) を持ちます。
  データは割り当てと一緒に動き、全稼働の共通の合計はありません。
  - 新規 → 稼働 → 保存: その割り当てには、その稼働の分だけが入ります。
  - 開く (または割合を変える) → 稼働 → 保存: それまでの利用記録に、その稼働の分を足します。
  - 利用記録の無い計画 (画面を開いたときの新しい計画、前回の稼働の割り当て) は、同梱の回数で並べます: このリリース用に
    計測した 12 分野の回数で、ページに入っています。

  12 分野: コーディング、エージェント、日本語、英語、エージェント A、エージェント B、コーディング 日、コーディング 英、
  Linux 運用 日、Linux 運用 英、セキュリティ 日、セキュリティ 英。どの分野も同じ重みです: expert は、どれかの分野で
  その層の中に占める割合の一番大きい値で並びます。
- **bank と データなし**: 各 bit 幅の expert は Hugging Face の `fiore-lab/GLM-5.3-EXL3-Experts-<N>bit` (N = 2, 3, 4, 5) を
  使います。どのノードでも幅ごとに別のディレクトリ (既定は `~/models/GLM-5.3-EXL3-Experts-<N>bit`) に、manifest と
  一緒に置きます。どれかのノードで bank が欠けている幅は「データなし」と出し、どのノードに何が無いかを示します。計画には
  使えず、表のその幅の行は データなし になり、割合を入れられません。
- **メモリ** ([ LAUNCH ]): 計画に対する各ノードのメモリ (expert、ほかの重み、KV、作業域、余裕) と判定 (収まる / ぎりぎり /
  入らない)。KV FP4 / FP8 には形式ごとに確保する KV サイズ (token と 1 ノードの GiB) が出ます。押した形式で起動します。
  KV はいつも、計画が残す空きを全部使います: 1 つの会話に Max model len、残りは前の会話のため。各ノードで空けておく量は
  OS に残す で決めます。
- **Max model len**: 1 回の要求 (prompt と返答の合計) の最長 (token): 131K / 262K / 524K / glm53.conf の CONTEXT / 最大 (選んだ
  KV 形式で計画に入る最長。エンジンは文脈のほかにも KV を要るので、KV サイズそのものにはなりません。pool のキャッシュは
  最低 512 token を残します)。入らないサイズは灰色です。ランチャーが切り詰めたときは、そのサイズを下に出します。既定は 最大 です。
  ランチャーは、このレーンでそのドラフターを使った起動が実際に使ったメモリから最大を出します (起動のたびに、ドラフターごとに
  測ります)。まだ測っていないあいだは組み込みの値に 2 GiB の余裕を足すので、最大は短めです (推定)。KV の行のサイズの左にも
  推定 か 実測 を出します。測るのは起動直後の何も
  動いていないときなので、最大で動かすと推論中にノードの空きが「OS に残す」量を少し割ることがあります。名前の横の i で
  この説明と、選んでいるドラフターが実測か推定かを見られます。
- **OS に残す**: 起動後に各ノードで空けておく量: 4 / 6 / 8 / 12 GiB (既定は glm53.conf の RESERVE_GB、4)。判定とエンジンの
  受け付けがこれを使い、多く残すほど KV に回せる量が減ります。
- **ドラフター**: MTP / DFlash2 / なし を KV の下で選び、それに合わせてメモリを見積もります。DFlash2 はライセンスの都合で
  同梱していません。自分でダウンロードして glm53.conf の DRAFTER に置き場所を書きます。全ノードにそろうまでは灰色で、理由が出ます。
- **ノード** (カードの見出し。エンジンが止まっている間): head (rank 0) はランチャーが動いているノードです。worker は台数に
  関係なく一度登録し (アドレスを入れて 追加)、台数ごとに使うものを一覧からチェックします (4 台なら 使う 3 / 3、8 台なら
  7 / 7)。rank は一覧の順です。一覧と台数ごとのチェックはレーンのパネル設定に残るので、どのブラウザで開いても戻ります。
  削除 で一覧から外します (どの台数のチェックからも外れます)。今のレーンが使っている worker は一覧に必ずあり、チェックを
  外して保存すると削除できます。台数 (ランチャーが 4 と 8 を出すとき) で台数を選びます。確認 は head と
  チェックした worker へパッケージを配り (tf-glm53 deploy)、tf-glm53 check で確かめます (ssh、ネットワーク、メモリ、NCCL、
  ファイル。ノードごとに ✓ / ✗ と理由。少し時間がかかります)。その一覧が全部 ✓ なら 保存 で glm53.conf の NODES に書き
  (元のファイルは横に控えを残す)、次の起動から使います。別の台数で保存するとレーンがその台数になります。保存 を押せない
  ときは横に理由が出ます。アドレスは ConnectX-7 のもの (NCCL が使うもの) で、どのノードにも全部の bank が要ります。新しい
  台数で一度起動して測るまで、見積もりは推定です。
- **起動**: 「起動」を 2 回 (起動 → 8 秒以内に 確定) 押します。読み込んだ層からサークルが点き (本物: エンジンの読み込みの進み)、
  終わると稼働パネルに切り替わります。
- **最適化した割り当て**: 起動は渡した表を読むだけで並べ替えないので、起動画面に エキスパート最適化 はありません。
  エンジンの動作中に最適化します (下)。停止のときエンジンに載っている表が前回の稼働になるので、起動画面はそれで開きます。
  後の起動でも使うときは 保存 し、開く で戻します。

## 稼働パネル (エンジン動作中)

- **サークル**: 本物の表示と演出があります。
  - decode: token ごとにモデルが選んだ expert が光って消えます (本物: エンジンの選択の記録)。
  - prefill: セルの点滅は演出です。内側から外側へ広がっていく輪は、いま計算している層を示します (prompt の区切りごとに
    1 周。prompt の進みから見積もります)。区切りで使われた expert は出していません: 数千 token の区切りではほぼ全部の
    expert が少しずつ使われ、光らせても地味だったためです。
  - 起動: expert の読み込みに合わせて伸びていくサークルは本物です (上の 起動)。

  prompt の計算中は番号順、decode が始まると使用順 (よく使われる順、9 時から) に並びます。
- **外周**: prompt の計算中は prefill の進み (本物)、decode 中は返答の文字が外周を回ります。
- **中心と下**: 中心に bpw (選ばれた expert の bit の平均) と幅ごとの選択の割合。サークルの下に prefill と decode の tok/s、
  直近 3 分の bpw の推移。
- **[ LAUNCH ]**: 停止と、サーバーの一覧: head (rank 0) と worker、それぞれの空きメモリ、GPU と CPU の温度 (CPU は
  ノードの温度ゾーンで最も高いもの。GB10 は CPU と GPU が 1 つのチップで、負荷時は GPU 自身の値より 6〜10 °C 高く出ます)。
  ランチャーが 5 秒ごとに読みます。ランチャーが出さない値は「—」です。
- **[ BIT ALLOC ]**: 載っている bit。見出しに起動で使った割り当て (新しい計画からなら 新規 · 未保存)。保存 で名前を付けて残せます。
  幅ごとに exp数、割合 (expert 数の割合)、利用率 (選択の割合)、GiB。平均bit、
  expertサイズ、KVサイズ (token と形式。例: 837K FP4)、ドラフター、MemAvailable、確保 (rank 0)。稼働パネルが数えるのはこの稼働の選択だけで、同梱の回数は
  ここには出ません。
- **停止**: 保存して停止 は、載っている bit と稼働の利用記録 (起動したときの記録 + この稼働の分) を 割り当ての名前 で保存して
  から止めます。保存せず停止 は何も保存しません。名前の既定は起動した元の割り当てで、上書きします (前の版はランチャーの
  ごみ箱へ)。別の名前も付けられ、既にある名前はもう一度押すと上書きします。

## 動作中のエキスパート最適化

- [ BIT ALLOC ] のメニューの「エキスパート最適化」で、載っている expert を稼働の利用記録 (起動したときの記録 + この稼働の
  選択) で並べ替えます (幅ごとの個数はそのまま)。よく選ばれる expert ほど広い bit になるので、同じメモリで選択の平均 bit が上がります。
  並べる回数は見積もりの欄の 利用記録 で選びます (decode / prefill / prefill 0.3 / decode 0.7)。押すたびに
  prefill 0.3 / decode 0.7 から始まり、選び直すと見積もりを取り直します。この稼働に prefill の回数がまだ無いときは、
  prefill だけが灰色で、既定は decode だけで並べます。
- 見積もりには、変わる expert の数、推論が止まる時間、会話のキャッシュが消えることが出ます。表示している間は 30 秒ごとに
  取り直し、「実行」は押した時点の回数で並べます。「実行」すると、走っている要求の
  終わりを待って層ごとに入れ替えます。結果は自動では保存しません。残すときは 保存 します。
  全面の入れ替え (75 層、9,756 個) は 4 ノードで 83〜90 秒でした。
- `TF_GLM53_MULTI` で動かしているエンジンは、動作中に bit を変えません。そこでは エキスパート最適化 の見積もりに「実行」の
  代わりに「起動用に保存」が出て、見積もりの bit に名前 (`opt-<時刻>`) を付けて保存します (推論は止まりません)。エンジンを
  止めて、起動画面の 開く でそれを選んで起動します。

## 表示設定

画面下の引き出し (表示設定):

- **全般**: 言語 (English / 日本語。既定はブラウザの言語)、データ (ライブ / シミュレーション と 再生を止める)、
  メモリの棒の見た目。
- **サークル**: 並べ方 (既定は 自動。9 時から)、残光 (既定は 短い)、未選択と選択の明るさ (24 段で既定は 6 と 19)、
  光の色 (bit ごとに変える / 1 色。既定は 1 色の青)。
- **文字と中心**: 外周の 文字 (既定は 表示して回さない)、数字 (既定は 7 セグ)、中心 のマス。
- **配色**: プリセット (既定は グリーン · 一色。ランダム で別の配色)。

設定はパッケージのディレクトリの `launch/panel-settings.json` 1 つに残る (`EXTRA_ENV` の `TF_PANEL_SETTINGS` で場所を
変えられます) ので、どのブラウザで開いても同じパネルになります。既定に戻す (2 回押し) はそのファイルから表示設定を外すので、
このレーンを開く全員の表示が既定に戻ります。言語とノードの設定は残ります。
