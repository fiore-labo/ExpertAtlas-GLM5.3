# Expert Atlas: コントロールパネル

パネルはランチャーが `http://<先頭ノード>:<ランチャーのポート>/panel` に出します。既定では全アドレスで、キーなしで待ち受けるので、
パネルに届く人は誰でもエンジンの起動・停止・変更ができます。閉じたネットワーク内に留めてください (`LAUNCHER_HOST=127.0.0.1` に
すると先頭ノードからだけになり、ほかの機械からは ssh のトンネル `ssh -L 8010:127.0.0.1:8010 <先頭ノード>` のあと
`http://127.0.0.1:8010/panel` で開きます)。
画面は 2 つあり、自動で切り替わります: エンジンが止まっている間は起動画面、動いている間は稼働パネルです。このリリースの
パネルは 4 ノードか 8 ノードで動きます (台数は起動画面の ノード で選びます)。

サークルは routed expert 19,200 個の地図です。内側が層 3、外側が層 77 で、1 周が 256 個です。

## 起動画面 (エンジン停止中)

- **計画** ([ BIT ALLOC ]): 各 expert を何 bit で読むかを決めます。画面は新しい計画で開きます (割合は前回の稼働のもの。稼働が
  まだ無いときは全部 3 bit)。前回の稼働の割り当てそのものや保存した割り当ては 開く で選びます。カードの見出しに、
  今の計画が何かを出します: 新規 · 未保存、前回の稼働、保存した割り当ての名前。
  - **割合**: 表に bit 幅ごとの expert の割合を入れます (5・4・3 bit。残りはデータのある一番狭い幅になり、合計はいつも
    100%)。曲線上のつまみを動かしても決められます。目盛りは 5 bit の端を 0% として数えます: 5 bit 10% は範囲
    0〜10% です。混ぜるときは、よく使われる expert ほど広い bit になります。並べる回数は prefill 0.3 / decode 0.7
    (expert の decode の割合を 0.7、prefill の割合を 0.3 で重みづけ。`ATLAS-TESTS.ja.md`) です。
  - **利用記録** (decode / prefill / prefill 0.3 / decode 0.7): 見るためのボタンです。選んだ回数で、曲線とつまみの読み
    (使用順で上から並べた expert が選択の何 % を持つか)、サークルの並び、利用率を出します。計画の bit は変わりません。
  - **新しい計画**: 割合を変える (入力かつまみ) と新しい計画 (新規 · 未保存) になり、計画の利用記録 (下) の順に並べます。
  - **開く**: 前回の稼働の割り当てと、保存した割り当ての一覧です。割合、平均 bit、いつ・どう作ったかが出ます。開いたものは
    bit そのまま計画になり、起動はその割り当てを使います。利用記録も一緒に付いてきます: 利用記録 と曲線はそれを出し、そこから
    割合を変えた計画もそれで並べ、どちらから起動した稼働もそれに足されます。割合を変えるまで bit は保存したままです。
    データの無い幅や、このレーンに無い bank を使う割り当ては開けません (理由を下に出します)。保存したものは 名前の変更 と
    削除 (もう一度押して確定) ができます。削除したものはランチャーのごみ箱へ移ります。
  - **保存**: 自動では保存しません。計画は、その稼働を止めるときに利用記録と一緒に保存します (下の 保存して停止。稼働パネルの
    保存 でもいつでも)。
- **利用記録**: 保存した割り当ては、それを保存した稼働の利用記録 (expert ごとの選ばれた回数、decode と prefill) を持ちます。
  データは割り当てと一緒に動き、全稼働の共通の合計はありません。
  - 新規 → 稼働 → 保存: その割り当てには、その稼働の分だけが入ります。
  - 開く (または割合を変える) → 稼働 → 保存: それまでの利用記録に、その稼働の分を足します。
  - 利用記録の無い計画 (画面を開いたときの新しい計画、前回の稼働の割り当て) は、同梱の回数で並べます: このリリース用に
    計測した 12 分野の回数で、ページに入っています。

  12 分野: コーディング、エージェント、日本語、英語、エージェント A、エージェント B、コーディング 日、コーディング 英、
  Linux 運用 日、Linux 運用 英、セキュリティ 日、セキュリティ 英。どの分野も同じ重みです: expert は、どれかの分野で
  その層の中に占める割合の一番大きい値で並びます。
- **[ WEIGHTS ]**: チェックポイントと expert の bank の場所です。どのノードでも同じパスに置きます。既定は、チェックポイントが
  `~/models/GLM-5.3-EXL3-Base` (Hugging Face の `fiore-lab/GLM-5.3-EXL3-Base`)、bank が `~/models/GLM-5.3-EXL3-Experts-<N>bit` です
  (`QUICKSTART.ja.md` の 2 節)。別の場所に置いたときは、行にディレクトリを書くか 参照 で選び、確認して保存 を押します。
  全ノードを見るのは、画面を開いたとき、行を変えたとき、必須のものが無い間は 15 秒ごとです。これは読むだけで、保存はしません。
  チェックポイントと 3 bit の bank は必須です。無いと行が赤くなり、ノードとリポジトリ名を示し、起動 は押せません。行のディレクトリが
  未保存の間も 起動 は押せません。ほかの幅は任意で、行を空にするか bank が見つからなければ、その幅を使わないだけです。
- **bank と データなし**: 各 bit 幅の expert は Hugging Face の `fiore-lab/GLM-5.3-EXL3-Experts-<N>bit` (N = 2, 3, 4, 5) を
  使います。どのノードでも幅ごとに別のディレクトリ (既定は `~/models/GLM-5.3-EXL3-Experts-<N>bit`) に、manifest と
  一緒に置きます。どれかのノードで bank が欠けている幅は「データなし」と出し、どのノードに何が無いかを示します。計画には
  使えず、表のその幅の行は データなし になり、割合を入れられません。
- **メモリ** ([ NODE ]): 計画に対する各ノードのメモリ (expert、ほかの重み、KV、作業域、余裕) と判定 (起動できます / 起動できます（余裕なし） /
  メモリ不足)。KV FP4 / FP8 には形式ごとに確保する KV サイズ (token と 1 ノードの GiB) が出ます。押した形式で起動します。
  KV はいつも、計画が残す空きを全部使います: 1 つの会話に Context length、残りは前の会話のため。各ノードで空けておく量は
  OS に残す で決めます。
- **Context length**: 1 回の要求 (prompt と返答の合計) の最長 (token): 131K / 262K / 524K / glm53.conf の CONTEXT_LENGTH / 最大 (選んだ
  KV 形式で計画に入る最長。エンジンは context のほかにも KV を要るので、KV サイズそのものにはなりません。pool のキャッシュは
  最低 512 token を残します)。入らないサイズは灰色です。ランチャーが切り詰めたときは、そのサイズを下に出します。パネルが書くまでの既定は 最大 です。この画面で選んだ値は選んだ時点で glm53.conf に書き（最大は数字で、その数字が動いたら書き直します。押していなければ起動のときに）、次に開くとその値が選ばれています。
  ランチャーは、このレーンでそのドラフターを使った起動が実際に使ったメモリから最大を出します (起動のたびに、ドラフターごとに
  測ります)。まだ測っていないあいだは組み込みの値に 2 GiB の余裕を足すので、最大は短めです (推定)。KV の行のサイズの左にも
  推定 か 実測 を出します。測るのは起動直後の何も
  動いていないときなので、最大で動かすと推論中にノードの空きが「OS に残す」量を少し割ることがあります。名前の横の i で
  この説明と、選んでいるドラフターが実測か推定かを見られます。
- **OS に残す**: 起動後に各ノードで空けておく量: 4 / 6 / 8 / 12 GiB (既定は glm53.conf の RESERVE_GB、4)。判定とエンジンの
  受け付けがこれを使い、多く残すほど KV に回せる量が減ります。
- **ドラフター**: MTP / DFlash2 / なし を KV の下で選び、それに合わせてメモリを見積もります。DFlash2 はライセンスの都合で
  同梱していません。自分でダウンロードして glm53.conf の DRAFTER に置き場所を書きます。全ノードにそろうまでは灰色で、理由が出ます。
- **ノード** (カードの見出し。エンジンが止まっている間): head (rank 0) はランチャーが動いているノードです。worker は台数に
  関係なく一度登録し (アドレスを入れて 追加)、台数ごとに使うものを一覧からチェックします (4 台なら 使う 3 / 3、8 台なら
  7 / 7)。rank は一覧の順です。一覧と台数ごとのチェックはレーンのパネル設定に残るので、どのブラウザで開いても戻ります。
  削除 で一覧から外します (どの台数のチェックからも外れます)。今のレーンが使っている worker は一覧に必ずあり、チェックを
  外して保存すると削除できます。台数 (ランチャーが 4 と 8 を出すとき) で台数を選びます。確認 は head と
  チェックした worker へパッケージを配り (tf-glm53 deploy)、tf-glm53 check で確かめます (ssh、ネットワーク、メモリ、NCCL、
  ファイル。ノードごとに ✓ / ✗ と理由。少し時間がかかります)。その一覧が全部 ✓ なら 保存 で glm53.nodes.conf に書き
  (glm53.conf は変えません。元のノードのファイルは横に控えを残す)、次の起動から使います。別の台数で保存するとレーンがその台数になります。保存 を押せない
  ときは横に理由が出ます。アドレスは、スイッチでは ConnectX-7 のもの (NCCL が使うもの)、リングでは LAN のもので、どのノードにも全部の bank が要ります。新しい
  台数で一度起動して測るまで、見積もりは推定です。
- **起動**: 「起動」を 2 回 (起動 → 8 秒以内に 確定) 押します。読み込んだ層からサークルが点き (本物: エンジンの読み込みの進み)、
  終わると稼働パネルに切り替わります。
- **起動の流れ**: 見出しの右のボタン (手順バーが出ている間、つまりエンジンが動く前の画面だけ) で開く画面です。0 起動 (先頭ノードで
  `./tf-glm53 up`) › 1 › 2 › 3 › 稼働 を、手順バーと同じ番号で 1 枚に並べます。各段の札は手順バーのボタンそのものです。閉じる か
  Escape で戻ります。
- **最適化した割り当て**: 起動は渡した表を読むだけで並べ替えないので、起動画面に エキスパート最適化 はありません。
  エンジンの動作中に最適化します (下)。停止のときエンジンに載っている表が前回の稼働になるので、起動画面はそれで開きます。
  後の起動でも使うときは 保存 し、開く で戻します。

## 稼働パネル (エンジン動作中)

- **サークル**: 本物の表示と演出があります。
  - decode: token ごとにモデルが選んだ expert が光って消えます (本物: エンジンの選択の記録)。
  - prefill: セルの点滅は演出です。内側から外側へ広がっていく輪は、いま計算している層を示します (prompt の区切りごとに
    1 周。prompt の進みから見積もります)。区切りで使われた expert は出していません: 数千 token の区切りではほぼ全部の
    expert が少しずつ使われ、光らせても地味だったためです。
  - 起動: expert の読み込みに合わせて伸びていくサークルは本物です (上の 起動)。

  prompt の計算中は番号順、decode が始まると使用順 (よく使われる順、9 時から) に並びます。
- **外周**: prompt の計算中は prefill の進み (本物)、decode 中は返答の文字が外周を回ります。
- **中心と下**: 中心に bpw (選ばれた expert の bit の平均) と幅ごとの選択の割合。サークルの下に prefill と decode の tok/s
  (decode は全部の要求の合計。同時に走るときは「decode 合計」。同時に走るときの prefill は、サークルが表示している要求の
  prompt を計算した時間あたり (decode を待つ時間は入れない。エンジンが出さなければ —))、直近 3 分の bpw の推移。
- **[ NODE ]**: 停止と、サーバーの一覧: 名前の右に head か worker、それぞれの空きメモリ、GPU と CPU の温度 (CPU は
  ノードの温度ゾーンで最も高いもの。GB10 は CPU と GPU が 1 つのチップで、負荷時は GPU 自身の値より 6〜10 °C 高く出ます)。
  ランチャーが 5 秒ごとに読みます。ランチャーが出さない値は「—」です。
  RDMA (RoCE の通信スレッドの場所を出すエンジンのとき): ノードごとの 2 本の通信スレッド (ノード間と DCP 組) の CPU
  (例: 0·10) とその種類 (A725 か X925)。表の下の 1 行は起動設定 (ROCE_PROXY_CORES: A725 に固定 (既定)、
  OS 任せ)。head は直近に動いた CPU、ほかのノードは起動時に固定した CPU で、OS 任せなら「—」。ランチャーなしでは
  専用のカード [ RDMA ] に出します。
  同時推論: エンジンが同時に扱う会話の数と、2 以上なら推論中の要求の数。
- **GPU の配分** (同時推論のエンジンが配分を出すときだけ。ほかは出ません): prompt の計算と decode 中の会話が重なる間の
  GPU の時間の分け方。スライダーは prefill 100% (prompt を先に。prefill の間は decode が止まります) から decode 100%
  (生成中の会話がある間、新しい prompt は待ち、実行中の prefill も止まります) まで 5% 刻み。その間の値では、その割合の
  時間を decode に回します。片方の仕事しかないときは、その仕事が GPU を全部使います。スライダーを離したときに送り
  (反映中… → 反映しました)、実行中の推論にも効きます。断られたら使っている値に戻り、赤で理由を出します。スライダーの下の
  点は、エンジンが起動時の値を出すときの起動時の値です。その下に、直近の重なりでエンジンが測った decode の割合
  (重なっている間は「重なり中」)。decode 100% では、待っている prompt の数と最長の待ち時間。それぞれの説明は、名前の横の ⓘ
  を押したときだけ出ます (Context length と同じ。もう一度押すか Escape で閉じます)。断られた理由の赤い行は ⓘ なしで出ます。
  優先 prompt (API では short_prompt): 新しく計算する tokens (キャッシュより後ろ。prompt の長さではありません) がこの数以下の prompt は、配分に
  かかわらず長いものより先に入り、その prefill は GPU を全部使います (その間 decode は止まります。止まる秒数は出しません)。− / + で 0・256・512・1K・2K・4K・8K・16K・32K、直接の入力もできます
  (0〜1,048,576。Enter か欄を離れたときに送ります)。0 で無効。実行中の prefill も追い越す (既定オフ): 実行中の長い
  prefill も優先 prompt に譲り、終わったチャンクから続けます (長い方が最大 1 チャンク遅れます)。値は毎秒エンジンに
  合わせるので、別の所での変更もここに出ます。ランチャーなしで起動したエンジン ([ NODE ] カードがない) では、同じものを
  専用のカード [ GPU SPLIT ] に出します (見出しに同時推論)。
- **[ REASONING CONTROL ]**（[ NODE ] の下。GPU の配分と同じ形で、動作中に変えられる思考の設定。API と設定の名前は `/v1/thinking` と `THINKING_*` のまま）: 思考の上限は、各応答の
  max_tokens（1 回の応答の上限）の 5%〜100%（上限なし）のスライダーです。そこに届くと、エンジンがモデルに思考を閉じさせ、残りで答えを書かせる
  ので、短い応答（ハーネスの max_tokens）でも答えの分が残ります。点で起動時の値を出します。
  中間整理 する（checkpoint）/ しない。整理する間隔は max_tokens の 10% から 100% までの
  スライダーです（最低 1,024 トークン。右端の 100% が既定で、上限まで整理しない。中間整理なしでは灰色、それ以外は思考の上限より前）。思考完了時整理 する（思考の上限に対する割合。持っていた割合、なければ
  glm53.conf の、なければ 100%）/ しない。どれも、変えた後に始まる要求から効き（反映中… → 反映しました。断られたら元に戻して
  赤で理由）、ランチャーが glm53.conf にも書くので次の起動もその値です。要求自身の予算や整理の指定が先です。起動画面（エンジン
  停止中）や、動作中に変えられないエンジンでは、同じカードで次の起動の値をすぐ glm53.conf に保存します（次回起動時反映）。エンジン設定の
  画面でも同じ 4 つを変えられ、どちらで変えても両方に出ます。
- **[ BIT ALLOC ]**: 載っている bit。見出しに起動で使った割り当て (新しい計画からなら 新規 · 未保存)。保存 で名前を付けて残せます。
  幅ごとに exp数、割合 (expert 数の割合)、利用率 (選択の割合)、GiB。平均bit、
  expertサイズ、KVサイズ (token と形式。例: 837K FP4)、ドラフター、MemAvailable、確保 (rank 0)。稼働パネルが数えるのはこの稼働の選択だけで、同梱の回数は
  ここには出ません。
- **停止**: 保存して停止 は、載っている bit と稼働の利用記録 (起動したときの記録 + この稼働の分) を 割り当ての名前 で保存して
  から止めます。保存せず停止 は何も保存しません。名前の既定は起動した元の割り当てで、上書きします (前の版はランチャーの
  ごみ箱へ)。別の名前も付けられ、既にある名前はもう一度押すと上書きします。

## 動作中のエキスパート最適化

- [ BIT ALLOC ] のメニューの「エキスパート最適化」で、載っている expert を稼働の利用記録 (起動したときの記録 + この稼働の
  選択) で並べ替えます (幅ごとの個数はそのまま)。よく選ばれる expert ほど広い bit になるので、同じメモリで選択の平均 bit が上がります。
  並べる回数は見積もりの欄の 利用記録 で選びます (decode / prefill / prefill 0.3 / decode 0.7)。押すたびに
  prefill 0.3 / decode 0.7 から始まり、選び直すと見積もりを取り直します。この稼働に prefill の回数がまだ無いときは、
  prefill だけが灰色で、既定は decode だけで並べます。
- 見積もりには、変わる expert の数、推論が止まる時間、会話のキャッシュが消えることが出ます。表示している間は 30 秒ごとに
  取り直し、「実行」は押した時点の回数で並べます。「実行」すると、走っている要求の
  終わりを待って層ごとに入れ替えます。結果は自動では保存しません。残すときは 保存 します。
  全面の入れ替え (75 層、9,756 個) は 4 ノードで 83〜90 秒でした。
- `TF_GLM53_MULTI` で動かしているエンジンは、動作中に bit を変えません。そこでは エキスパート最適化 の見積もりに「実行」の
  代わりに「起動用に保存」が出て、見積もりの bit に名前 (`opt-<時刻>`) を付けて保存します (推論は止まりません)。エンジンを
  止めて、起動画面の 開く でそれを選んで起動します。

## エンジン設定

右上の切り替え「推論（停止中は 起動）| エンジン設定」で、再起動が必要な設定（glm53.conf）を開きます（この口のない
ランチャーでは切り替えは出ません）。動作中に変えられる設定は推論画面に残ります: GPU の配分、[ REASONING CONTROL ]（変えるたびに glm53.conf にも書きます）と
エキスパート最適化です。

- 各行に名前、(i)（対象・設定するもの・目的・例・関係と既定値）、glm53.conf と違えば「変更」、キー。規則（tf-glm53 と同じ確認）
  に合わない値は赤になり、保存 は押せません。今は選べない選択肢は灰色で、指すと理由が出ます。
- **KV と context length**: Context length（CONTEXT_LENGTH: 1 回の要求の最長）と KV サイズ（KV_SIZE: KV キャッシュ全体で、
  すべての会話が分け合う 1 つのプール。パネルからの起動はいつも計画が残す空きを全部使うので、これは `tf-glm53 up` のための値）、
  KV の形式。
- **思考と答えの大きさ**: max_tokens（1 回の応答の上限。MAX_TOKENS_SHARE、スライダー。context length に対する割合で既定 70%。max_tokens を付けない要求に使う。
  クライアントが max_tokens を送ればそちらが優先。古い glm53.conf の MAX_TOKENS はスライダーを保存するまで優先し、保存で消える）と、思考の上限（その割合、
  THINKING_SHARE。保存すると古い THINKING_BUDGET は 0）。思考の上限・中間整理・整理する間隔（THINKING_FOLD_SHARE）・思考完了時
  整理には「即時反映」の札が付き、稼働中は保存すると即時反映します（どれを反映したかを知らせます）。推論画面の [ REASONING CONTROL ] でも
  同じ値を変えられます。中間整理ありでは上限に「仮想」の札が付きます: 書いたトークンの数で数え、整理で KV
  から外した思考も数えるので、context length を超えられます。グループ名の横の ⓘ は、
  設定した値で応答の内訳を割合で描きます。大きさは prompt ごとに変わります。中間整理（THINKING_FOLD と、サイズの目安は整理する思考に対する割合で既定 70%。中間と完了時の両方に効く）と思考完了時整理
  （する・しない、既定はしない。するのときは「思考の上限の ○○% 以上の思考がおこなわれたら整理する」。数えるのは最後に整理してからの思考で、始めは 100%。THINKING_FOLD_AT_CLOSE_SHARE で、しないは 0）はそれぞれのグループです。残りのお知らせもする・しないです（するのときは何トークンごとか。始めは 5,000。THINKING_NOTICE で、しないは 0）。
- エンジンが動いている間、ドラフター、同時推論、KV の形式、context length、KV サイズ、OS に残すメモリは動いている値を出します。起動のあとに保存した行は、横に「次回起動時反映: X」と出します。保存するのは変えた行だけです。停止中は glm53.conf の値です。
- 重み、DFlash2 のモデル、ノードはここでは見るだけで、確かめる場所で変えます（起動画面の [ WEIGHTS ] の 確認して保存 とノード確認。全ノードで通ったら保存し、通らなければ保存せず行に理由を出します）。
  API のポートはエンジンが止まっている間だけ、パネルのポートはランチャーを起動し直したときから変わります。
  上級（開発用）に prompt の区切り、SP、切り方の直し、EXTRA_ENV があります。
- 変更はその時点で書きます: 選ぶものはすぐ、入力欄は離れたときか Enter、スライダーは離したとき（glm53.conf に。写しは glm53.conf.bak-<時刻> に、多くて 10 分に 1 回）。規則に合わない値は書かず、理由を出します。規則でつながる行（同時推論と DFlash2 の保存数など）は、合うようになったら一度に書きます。「元に戻す」で待っている変更を取り消せます。動いているエンジンはそのままで、
  その行に「保存済み · 次回起動時反映」が付きます。**再起動して反映** は一度確認したあと、停止と同じ問い（この稼働の
  利用記録を名前で保存するか）を出し、ランチャーがエンジンを止めて、保存した設定と同じ bit で起動し直します。

## 表示設定

画面下の引き出し (表示設定):

- **全般**: 言語 (English / 日本語。既定はブラウザの言語)、データ (ライブ / シミュレーション と 再生を止める)、
  メモリの棒の見た目。
- **サークル**: 並べ方 (既定は 自動。9 時から)、残光 (既定は 短い)、未選択と選択の明るさ (24 段で既定は 6 と 19)、
  光の色 (bit ごとに変える / 1 色。既定は 1 色の青)。
- **文字と中心**: 外周の 文字 (既定は 表示して回さない)、数字 (既定は 7 セグ)、中心 のマス。
- **配色**: プリセット (既定は グリーン · 一色。ランダム で別の配色)。

設定はパッケージのディレクトリの `launch/panel-settings.json` 1 つに残る (`EXTRA_ENV` の `TF_PANEL_SETTINGS` で場所を
変えられます) ので、どのブラウザで開いても同じパネルになります。既定に戻す (2 回押し) はそのファイルから表示設定を外すので、
このレーンを開く全員の表示が既定に戻ります。言語とノードの設定は残ります。
