# Expert Atlas: コントロールパネル

パネルはランチャーが `http://<先頭ノード>:<ランチャーのポート>/panel` で出します。ページ自体にキーは要りません。サーバーに
API キーがあるときは、一度だけ `/panel#key=<キー>` で開きます。ページはそのタブの間キーを持ち、API に付けて送ります。
画面は 2 つあり、自動で切り替わります: エンジンが止まっている間は起動画面、動いている間は稼働パネルです。このリリースの
パネルは 4 ノードで動きます。

サークルは routed expert 19,200 個の地図です。内側が層 3、外側が層 77 で、1 周が 256 個です。

## 起動画面 (エンジン停止中)

- **計画** ([ BIT ALLOC ]): 各 expert を何 bit で読むかを決めます。PRESET (前回 = 前回の稼働の割り当てそのまま。稼働が
  あるときだけ出ます。精度、均衡、メモリ、4 bit、3 bit) を選ぶか、曲線上のつまみで 5 / 4 / 3 / 2 bit の範囲を動かします。
  稼働がまだ無いときの計画は全部 3 bit です。混ぜるときは、よく使われる expert ほど広い bit になります。何で並べるかは
  利用記録 (decode / prefill / 両方) で選びます。
- **並べる元**: 計画をどの回数で並べたか。
  - 同梱 (12 分野): このリリース用に計測した使用回数で、ページに入っています。この環境で稼働を保存するまでは、計画は
    これで並べます。
  - 保存した稼働: この環境で停止のときに保存した稼働。最初の稼働を保存したら、計画はそれだけで並べ、同梱の回数は
    使いません。
  - なし: 回数がまったく無いとき。混ぜる計画は、どの層にも各幅を同じ割合で割り当てます。

  12 分野: コーディング、エージェント、日本語、英語、エージェント A、エージェント B、コーディング 日、コーディング 英、
  Linux 運用 日、Linux 運用 英、セキュリティ 日、セキュリティ 英。どの分野も同じ重みです: expert は、どれかの分野で
  その層の中に占める割合の一番大きい値で並びます。
- **bank と データなし**: 各 bit 幅の expert は Hugging Face の `fiore-lab/GLM-5.3-EXL3-Experts-<N>bit` (N = 2, 3, 4, 5) を
  使います。どのノードでも幅ごとに別のディレクトリ (既定は `~/models/GLM-5.3-EXL3-Experts-<N>bit`) に、manifest と
  一緒に置きます。どれかのノードで bank が欠けている幅は「データなし」と出し、どのノードに何が無いかを示します。計画には
  使えず、その幅が要るプリセットは灰色になります。
- **メモリ** ([ LAUNCH ]): 計画に対する各ノードのメモリ (expert、ほかの重み、KV、作業域、余裕) と判定 (収まる / ぎりぎり /
  入らない)。KV FP4 / FP8 には形式ごとに確保できる KV サイズ (token) が出ます。押した形式で起動します。
- **文脈サイズ**: 1 回の要求 (prompt と返答の合計) の最長 (token): 131K / 262K / 524K / glm53.conf の CONTEXT / 最大 (選んだ
  KV 形式で計画に入る最長)。入らないサイズは灰色です。ランチャーが切り詰めたときは、そのサイズを下に出します。
- **STORE サイズ**: 文脈とは別に、前の会話のために残しておく token: glm53.conf の STORE / 100K / 500K / 最大 (文脈の残りの KV
  全部。計画が見積もりの間は、ランチャーが 2 GiB 多く残します)。KV は文脈が先で、入らない STORE は灰色です。
- **OS に残す**: 起動後に各ノードで空けておく量: 4 / 6 / 8 / 12 GiB (既定は glm53.conf の RESERVE_GB、4)。判定とエンジンの
  受け付けがこれを使い、多く残すほど KV に回せる量が減ります。
- **ドラフター**: MTP / DFlash2 / なし を KV の下で選び、それに合わせてメモリを見積もります。DFlash2 はライセンスの都合で
  同梱していません。自分でダウンロードして glm53.conf の DRAFTER に置き場所を書きます。全ノードにそろうまでは灰色で、理由が出ます。
- **ノード** (カードの見出し): rank 順のノード。head (rank 0) はランチャーが動いているノードです。worker のアドレスは
  エンジンが止まっている間に変えられます。確認 は一覧のノードへパッケージを配り (tf-glm53 deploy)、tf-glm53 check で確かめます
  (ssh、ネットワーク、メモリ、NCCL、ファイル。ノードごとに ✓ / ✗ と理由。少し時間がかかります)。その一覧が全部 ✓ なら 保存 で
  glm53.conf の NODES に書き、次の起動から使います。
- **起動**: 「起動」を 2 回 (起動 → 確定) 押します。読み込んだ層からサークルが点き、終わると稼働パネルに切り替わります。
- **エキスパート最適化** (割り当て の下): 前回の稼働の割り当てを、その稼働の選択で並べ替えます (幅ごとの個数はそのまま)。
  見積もりでは変わる expert を新しい色でサークルに出します。「実行」で `sort-YYYYMMDD-HHMMSS` として保存し、次の起動の
  計画にします。前回の稼働が要るので、新しい環境では稼働を保存するまで押せません。

## 稼働パネル (エンジン動作中)

- **サークル**: トークンごとに選ばれた expert が光ります。prompt の計算中は番号順、decode が始まると使用順 (よく使われる順、
  9 時から) に並びます。
- **外周**: prompt の計算中は prefill の進み、decode 中は返答の文字が外周を回ります。
- **中心と下**: 中心に bpw (選ばれた expert の bit の平均) と幅ごとの選択の割合。サークルの下に prefill と decode の tok/s、
  直近 3 分の bpw の推移。
- **[ BIT ALLOC ]**: 載っている bit。幅ごとに exp数、割合 (expert 数の割合)、利用率 (選択の割合)、GiB。平均bit、
  expertサイズ、KVサイズ (GiB と token)、ドラフター、MemAvailable、確保 (rank 0)。稼働パネルが数えるのはこの稼働の選択だけで、同梱の回数は
  ここには出ません。
- **停止**: この稼働の利用記録を学習データに足すかを聞きます (保存して停止 / 保存せず停止)。

## 動作中のエキスパート最適化

- 割り当て の「エキスパート最適化」で、載っている expert をこの稼働の選択で並べ替えます (幅ごとの個数はそのまま)。よく選ばれる
  expert ほど広い bit になるので、同じメモリで選択の平均 bit が上がります。
- 見積もりには、変わる expert の数、推論が止まる時間、会話のキャッシュが消えることが出ます。「実行」すると、走っている要求の
  終わりを待って層ごとに入れ替え、割り当てを保存します。全面の入れ替え (75 層、9,756 個) は 4 ノードで 83〜90 秒でした。
- `TF_GLM53_MULTI` で動かしているエンジンは、動作中に bit を変えません。割り当ての保存だけをします。エンジンを止めて起動画面で
  「エキスパート最適化」をすれば、次の起動に同じ結果を使えます。

## 表示設定

画面下の引き出し (表示設定):

- **全般**: 言語 (English / 日本語。既定はブラウザの言語)、データ (ライブ / シミュレーション と 再生を止める)、
  メモリの棒の見た目。
- **サークル**: 並べ方 (既定は 自動。9 時から)、残光、光の色 (bit ごとに変える / 1 色)。
- **文字と中心**: 外周の 文字、数字、中心 のマス。
- **配色**: プリセット (既定は グリーン · 一色。ランダム で別の配色)。

設定はパッケージのディレクトリの `launch/panel-settings.json` 1 つに残る (`EXTRA_ENV` の `TF_PANEL_SETTINGS` で場所を
変えられます) ので、どのブラウザで開いても同じパネルになります。
